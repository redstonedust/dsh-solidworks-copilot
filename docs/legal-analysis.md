# 部署时自动拉取上游 skill 是否违法

对象：`https://github.com/wzyn20051216/solidworks-automation-skill`（下称"上游"）
结论先行：**在保留署名与许可全文的前提下，部署时自动拉取不构成违法**。MIT 已经把"使用、复制、修改、合并、发布、再许可、销售"全部预先授权，且**不限制用途**（含商用）。自动拉取在技术上就是"复制"，落在授权范围内，不构成侵权。

以下是逐条依据和边界。

---

## 一、上游的许可事实（已核对文件，非推测）

| 文件 | 内容 | 影响 |
|---|---|---|
| `LICENSE` | MIT，`Copyright (c) 2026 SolidWorks Automation Skill Contributors` | 唯一的实质义务：在副本或实质性部分中保留版权声明与许可全文 |
| `README.md` | 仅标注 `License: MIT`，指向 `LICENSE` | 无附加条款 |
| `CONTRIBUTING.md` | 无 CLA、无版权转让、无商用限制条款 | 贡献者按 MIT 入栈 |
| `SECURITY.md` | 说明无商业代码签名、需核对 Release SHA-256 | 安全建议，不是许可限制 |
| 全仓库 `license`/`商用`/`禁止` 检索 | 未发现"禁止商用""仅限个人使用"字样 | 无额外限制 |
| 二进制捆绑 | 仓库内无 `.exe`/`.dll`/`.pyd`，无第三方 LICENSE/NOTICE | 不涉及第三方二进制再分发 |

## 二、MIT 允许什么、要求什么

MIT 正文的四段结构：

1. **授权段**：授予不受限制的权利，包括 use / copy / modify / merge / publish / distribute / sublicense / sell。→ 拉取、复制、改造、商用、再分发都在授权内。
2. **条件段**：`The above copyright notice and this permission notice shall be included in all copies or substantial portions of the Software.` → 这是唯一硬性条件。
3. **免责段**：AS IS，无担保。
4. **责任限制段**：不承担损害赔偿责任。

所以判断标准只有一条：**你有没有把版权声明和许可全文带上去**。

## 三、三种部署形态的风险与义务

| 形态 | 你是否在"分发" | 义务 | 风险 |
|---|---|---|---|
| **A. 部署时从上游 git 拉取**（本仓库做法） | 否。代码在用户机器上由用户自己的 git 从上游获取 | 实质上零；仍建议附 NOTICE 说明来源与钉死版本 | 最低 |
| B. 把上游文件 vendor 进你的 release 包 | 是 | 必须随包携带上游 `LICENSE`、版权行、以及说明文件 | 低，漏带署名才是问题 |
| C. 修改上游后分发 | 是（衍生作品） | 同上；且不得声称修改版是上游官方版本 | 低 |

本仓库采用 A：不内置上游代码，只放一个拉取脚本 + `NOTICE` + `licenses/UPSTREAM-MIT.txt`。既满足 MIT 的署名要求，也不产生"再分发"这件事本身。

## 四、MIT 不管、但会咬人的三件事

### 1. 商标（最容易踩）

MIT 只授权著作权，**不授予商标权**。`SOLIDWORKS` 是 Dassault Systèmes SolidWorks Corporation 的注册商标。

- 可以：用文字指明兼容对象，例如 "for use with SOLIDWORKS"、"SolidWorks automation skill"。
- 不可以：用其 logo、把产品命名为 `SolidWorks XXX`、暗示官方合作/认证/背书、在宣传图里用其品牌视觉。
- 判断标准是**是否造成来源混淆**，不是有没有出现这个词。README 里那段商标声明就是为此存在的。

### 2. 上游自己写明的使用前提

上游 README 第 50 行：`SolidWorks | 2024 或 2026，需合法许可`。这是**它的使用前提**，不是许可条款，不改变 MIT 的授权范围，也不会因为用户环境不合规而把责任转给你。

但要注意边界：**拉取上游 skill ≠ 分发 SolidWorks 本体或其破解件**。如果你的插件部署流程里顺带做了授权绕过、补丁替换、许可服务器搭建，那部分完全在 MIT 覆盖范围之外，性质由那部分行为单独判断——与本插件无关，也不该写进本插件。

### 3. 出口管制与制裁名单

MIT 许可的纯软件、无加密实现，不落入常见出口管制清单。无需额外处理。

## 五、中国法视角

| 法律 | 判断 |
|---|---|
| 《著作权法》 | MIT 是著作权人预先作出的授权许可。复制、发行落在许可范围内，**不构成侵权**（第 53 条意义上的"未经许可"不成立）。条件未满足（删署名）时才转为侵权。 |
| 《商标法》第 57 条 | 构成侵权需"在同一种商品上使用相同商标"。作为兼容性说明的**指示性使用**，不指向商品来源，通常不构成侵权；造成混淆才可能落入第 57 条第（七）项。 |
| 《反不正当竞争法》 | 只要不使人误认为你与 Dassault 存在特定联系（第 6 条混淆行为），即无风险。 |
| 平台规则（GitHub ToS） | fork、镜像、自动拉取均在平台允许范围内；这属于平台政策，不是法律。 |

## 七、一句话总结

拉取 MIT 代码本身不是问题，**删掉署名、冒用商标、或把许可绕过打进自己的分发物**才是问题。前两件事靠 `NOTICE` + README 商标段解决，第三件事只要你的插件只做"取代码"就不存在。
